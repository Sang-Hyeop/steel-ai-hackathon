# Smart Tool Box · STBM

QR 접속, 역할별 공구 대시보드, 촬영·확인·출납 저장을 위한 Flask 웹 앱입니다.

## 실행 파일

**`SmartToolBox_실행.py`를 실행하세요.**

```sh
conda activate safety
python SmartToolBox_실행.py
```

서버가 시작된 뒤 기본 브라우저가 자동으로 열립니다. 기본 주소는 http://127.0.0.1:8001/ 이며 포트가 사용 중이면 다음 빈 포트를 선택하고 실제 주소를 터미널에 표시합니다. 종료는 Control+C입니다.
이 Mac에서는 다른 Python으로 실행해도 `/opt/anaconda3/envs/safety/bin/python`이 있으면 자동으로 전환합니다. 다른 컴퓨터에서는 먼저 필요한 환경과 패키지를 설치하세요.

```sh
python -m pip install -r requirements.txt
```

`app.py`는 서버 코드입니다. 브라우저 자동 열기는 `SmartToolBox_실행.py`가 담당합니다.

## 계정

- 관리자: 관리자 / 1234
- 작업자: 김상협, 강라온, 박회승, 이수민, 최인승 / 모두 1234

개발·시연용 계정입니다. 비밀번호는 scrypt 해시, 로그인 정보는 서명된 세션 쿠키로 처리합니다. 관리자 기능은 서버에서도 권한을 검사합니다.

## 화면

- 관리자 사이드바: 운영 대시보드, 공구·재고 관리, 출납 이력, 사용자별 출납 현황
- 작업자: 개인 대여 현황, 공구 대여·반납, 개인 이력
- 대여·반납: 촬영 또는 사진 선택 → 인식 또는 수동 입력 → 항목 수정·추가·삭제 → 최종 확인 → 저장 완료
- 반납 완료 KPI는 반납 처리 건수이며 공구 수량 합계와 다릅니다.
- 처리 상세는 여러 공구를 같은 ID로 묶어 보여줍니다.
- 라이트·다크 모드 설정은 브라우저에 저장됩니다. PC·태블릿·모바일 레이아웃을 지원합니다.

## 카메라와 AI 상태

카메라 시작·촬영·사진 미리보기·재촬영·이미지 선택·인식 요청·오류 안내를 구현했습니다. 출납 확정 시 촬영 사진은 `instance/event_photos/`에 JPEG로 저장되며, 출납 이력 상세와 **이벤트 사진** 탭에서 확인할 수 있습니다. 수동 입력만 하고 사진이 없으면 사진 없이 저장됩니다.

**최종 모델은 `models/tools_yolo11n_v4.pt`입니다.** PC 실행과 QR/휴대폰 실행(`SmartToolBox_휴대폰_실행.py`) 모두 같은 가중치를 사용합니다(`model_config.py`, imgsz 640 / conf 0.35).
인식 결과는 자동 확정하지 않으며, 사용자가 확인·수정한 뒤 저장합니다. 지원 클래스 매핑은 `recognition.py`의 `ALIASES`입니다.

권한 거부·카메라 없음·촬영 실패·인식 실패·탐지 없음 상태에 대한 안내를 제공합니다. 현장 정확도는 계속 확인·수정 흐름을 전제로 합니다.

## QR과 휴대폰 접속

관리자 운영 화면의 QR은 웹 접속용이며 개별 공구를 식별하지 않습니다. 연결 주소는 환경변수로 설정합니다.

```sh
STBM_PUBLIC_URL=https://your-host.example/ python SmartToolBox_실행.py
```

기본 서버는 이 컴퓨터만 접속하도록 구성했습니다. URL만 바꾼다고 휴대폰 접속이 열리지는 않습니다. 실제 휴대폰 접속은 별도 HTTPS 배포 또는 승인된 터널 구성이 필요합니다. 배포·터널은 이번에 구성하지 않았습니다.
실시간 카메라는 HTTPS 또는 localhost에서 동작합니다.

## 데이터

- SQLite: `instance/stbm.sqlite3`
- 세션 서명 키: `instance/session.key`
- 모두 Git 제외. 기존 사용자·재고·출납을 유지하며 기존 DB에는 처리 상태 열을 자동 추가합니다.
- 테스트·시연·운영 재고와 기록은 독립 관리합니다. 신규 공구 보유 수량은 0개입니다.
- 재고 수정은 사유·이전·이후 수량·관리자·시간을 저장합니다.
- 출납 이벤트와 공구별 상세 항목을 같은 트랜잭션에 저장합니다.
- 중복 토큰, 초과 대여·반납, 음수·소수 수량, 오래된 재고 수정 요청을 차단합니다.
- 동시 출납은 SQLite 쓰기 트랜잭션으로 검증과 저장을 묶습니다.
- 저장 성공 응답 이후에만 완료 화면을 표시합니다. 네트워크 오류 후 같은 확인창에서 재전송하면 같은 토큰을 사용합니다.
- 다른 사용자의 변경 사항은 새로고침 시 조회하며, 확정 시 서버의 최신 수량을 다시 검사합니다.
- 이력 화면은 최근 200건의 처리에 대해 검색·유형·사용자 필터를 제공합니다.

## 검증

```sh
python -m unittest discover -v
```

7개 테스트: 계정·권한, 영속 저장·부분 반납, 잘못된 수량·중복·동시 요청, 저장 실패 롤백, 다중 항목 처리·KPI, QR·AI 미연결 상태.
저장 실패 검증에서 의도한 DB 오류 로그가 출력됩니다. 임시 DB를 사용해 운영 데이터를 변경하지 않습니다.
브라우저에서 관리자 재고 변경, 작업자 복수 공구 대여·확인·완료, 상세 조회, 사용자 현황, 1440px PC·390px 모바일, 라이트·다크 모드를 확인했습니다.

## 제외 범위

AI 작업 준비 추천, 파손·분실·지연 알림, 개별 공구 QR은 최종 요구사항에 따라 추가하지 않았습니다. 현장 촬영 정확도 추가 검증과 상시 HTTPS 배포는 남아 있습니다. 로컬 QR/휴대폰 터널 실행에는 최종 모델이 연결됩니다.
