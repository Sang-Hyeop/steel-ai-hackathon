# 공구 감지 학습

환경은 conda safety, 모델은 Ultralytics YOLO11n입니다. 분류 순서는 screwdriver / wrench / pliers / hammer입니다. 펜치류에는 니퍼·펜치·플라이어가 포함됩니다. 렌치는 AI-Hub 분류 336이며 몽키스패너·파이프렌치는 제외합니다.

## 현재 사용하는 데이터: v2

이전 v1 변환에서 EXIF 회전을 반영하지 않아 일부 정답 위치가 어긋났습니다. v1 데이터·모델은 보존하지만 성능 판단과 신규 학습에 사용하지 않습니다.

1. `python tools/prepare_aihub_v2.py`: EXIF 회전을 적용합니다. 보정 후 이미지 크기와 원본 JSON 크기가 다른 사진은 제외합니다. AI-Hub Validation을 공개 진단용 test로 먼저 확보하고 Training을 학습/검증으로 분리합니다. 같은 원본 이름과 동일 픽셀 중복을 제외합니다.
2. `python tools/crop_aihub_v2.py`: 원본 해상도에서 공구 주변 문맥을 잘라냅니다. 일부만 보이는 다른 대상 공구가 들어온 크롭, dHash 거리 6 이하 유사 크롭, label_quarantine.json에 등록된 의심 원본은 제외합니다. 유사도 판정과 부분 표본 검수는 전체 수동 검수를 대체하지 않습니다.
3. `python tools/train_tools.py --epochs 5 --name yolo11n_full_v2 --skip-test`: 원본 사전학습 가중치에서 전체 학습 데이터로 320 해상도 학습을 시작합니다. 기본 배치 16, CPU 스레드 4입니다. 같은 이름을 재사용하면 Ultralytics가 별도 번호 폴더를 만들 수 있습니다.
4. `python tools/evaluate_detector.py runs/yolo11n_full_v2/weights/best.pt --data data/processed/aihub_4class_crops_v2 --name corrected_val_v2`: 검증용 사진에서 탐지 지표와 종류별 개수 일치율을 확인합니다. 실제 추론도 기본 320을 사용합니다.

v2 크롭 수: 학습 4,602장 / 검증 528장 / 공개 진단 765장. 원본 단위 분리와 라벨 형식 검사를 통과했습니다. 원본 EXIF 3 사진 151개에 회전 보정을 적용했으며, 보정 후 크기가 맞지 않는 원본 281개는 준비 단계에서 제외했습니다. 의심 분류 원본 1개는 격리했습니다.

## 평가 한계

공개 test 자료는 이미 이전 분석에 사용했으므로 새로운 독립 최종 평가라고 부르지 않습니다. 크롭 평가는 원본 전체 사진이나 실제 휴대폰 촬영 성능과 다릅니다. 합성 사진 역시 실제 현장 검증을 대신할 수 없습니다. 모델 채택 전 새 휴대폰 사진으로 추가 검증해야 합니다. Roboflow 데이터는 누락 라벨 검수 전이므로 현재 학습에서 제외합니다.

원본 출처는 사용자가 내려받은 AI-Hub 037.Small object detection을 위한 이미지 데이터의 공구 부분입니다. 이용조건은 원 배포처 조건을 따릅니다. 원본 ZIP을 수정하지 않으며 변환 이미지와 모델은 로컬에 보관합니다. 웹 서버와 GitHub에 자동 업로드하지 않습니다.


## v3 진행 중: 렌치 범위 통합

사용자 결정에 따라 AI-Hub 336 스패너/렌치와 341 몽키스패너를 모두 YOLO 클래스 1(wrench, 화면 표시 렌치)로 통합합니다. 전체 클래스 수와 순서는 4개로 유지합니다. 파이프렌치(346)는 이번 추가 범위에 포함하지 않습니다.

`python tools/train_unified_wrench_v3.py`는 원본 변환 → 문맥 크롭 → 원본 단위 분리·좌표 검사 → YOLO11n 5회 학습 → 같은 v3 검증 데이터에서 v2/v3 비교를 순서대로 실행합니다. 기존 v2 데이터·가중치는 유지하며 앱 모델은 자동 교체하지 않습니다. 로그에 V3_TRAINING_AND_VALIDATION_COMPLETE가 있어야 전체 과정이 완료된 것입니다.

몽키스패너 원본 정답 수는 TL 992개, VL 127개입니다. 중복·크기 불일치·부분 크롭 제외 전 수량으로 최종 학습 수량과 다릅니다. 결과는 runs/v3_on_unified_v3_val/metrics.json에 저장됩니다. 실제 새 촬영 사진 성능은 별도 검증이 필요합니다.


## v4 대기 중: 공구 크기 다양화

사용자 제공 두 사진에서 v2가 대부분 공구를 놓쳤습니다. 640 추론 및 단순 이미지 축소 여백 추가로 해결되지 않았습니다. 크기 분포는 개선 가설이며 단독 원인으로 확정하지 않습니다.

train_scale_v4.py는 v3 완료 로그를 확인한 뒤 실행됩니다. crop_aihub_v4.py에서 학습용 원본만 문맥 배율 1.4/2/4 중 하나로 결정적으로 배정해 큰 공구와 작은 공구를 섞습니다. 정답 누락을 막기 위해 일부만 보이는 다른 대상 공구가 포함된 크롭은 제외합니다. 원본 단위 train/val/test 격리와 좌표 범위를 검사합니다. 검증·공개 진단 사진은 v3 경로를 그대로 참조해 비교 대상을 고정합니다.

YOLO11n 원본 사전학습 가중치에서 최대 15회 학습하며 patience 10 조기 종료를 사용합니다. v3와 학습량·크기 분포가 함께 달라지므로 원인별 효과를 분리한 실험은 아닙니다. 학습 후 같은 v3 검증 자료와 별도 사용자 진단 사진에서 평가합니다. 제공 사진은 학습에 넣지 않습니다. 앱 가중치는 자동 교체하지 않습니다.

## v5 진행 중: 다중 공구 장면 파인튜닝

실사용자 진단 사진에서 v2~v4가 완전 일치하지 않았습니다. 공통 실패는 (1) 테이블 위 여러 공구 장면, (2) 망치 누락, (3) 렌치↔펜치 부분 중복 박스입니다. 진단 사진은 학습에 넣지 않습니다.

1. `python tools/build_scenes_v5.py`: v4 단일 공구 크롭으로 합성 다중 공구 장면(~2400)을 만들고, 클래스별 실크롭 일부(~1600)를 함께 둡니다. 망치 샘플 비중을 높입니다. 검증은 기존 v3 val을 유지합니다.
2. `python tools/train_scene_v5.py`: v4에서 imgsz 640, 12 epoch 파인튜닝 후 평가했습니다. 진단 실사진에서 회귀하여 **최종 채택하지 않았습니다.** 후보 가중치는 `models/candidates/tools_yolo11n_v5.pt`에 보관합니다.
3. 앱 후처리: `recognition.filter_detections`가 겹치는 서로 다른 클래스 박스 중 점수가 비슷하면 더 큰 박스를 남깁니다.

**최종 고정 모델은 v4**입니다. PC·QR/휴대폰 실행 모두 `model_config.py` → `models/tools_yolo11n_v4.pt`를 사용합니다.
